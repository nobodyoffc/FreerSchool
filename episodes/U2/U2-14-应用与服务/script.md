## 目标

看完这一集，观众能够：
- 知道主页的"应用"和"服务"是链上登记的目录：谁都能发布，没有谁审批上架，每一条都记着所有者和链上评分；
- 分清服务和应用：服务是别人运行着、按用量收费的服务器（BASE、DOCK、DISK 等），应用是你装在设备上用的软件，应用要连接服务；
- 会浏览、排序、搜索、查看详情，凭所有者、总评分和总币天销毁判断一条登记靠不靠得住；
- 知道每条登记有自己的 ID（应用 AID、服务 SID，即发布它的交易 ID）；服务可以有掌柜处理收支，应用和服务都可以有服务员处理客户消息；
- 会用币天给应用或服务评分；会把不想看到的条目隐藏；
- 知道设置 DOCK、DISK 时，选的就是这份服务目录里的服务，可以按评分和币天销毁挑选；
- 知道主页的"协议"和"代码"用法相同，主要供开发者使用。

本集独立成篇，不承前启后。发布自己的应用和服务不在本集讲。

## 核对依据

- 入口：主页"应用"（`menu_app` → `AppActivity`，标题"应用"）、"服务"（`menu_service` → `ServiceActivity`，标题"服务"）。两页布局相同
- 列表页（`activity_app.xml`）：顶部搜索框，"搜索范围""排序字段"下拉；排序按钮"名称""所有者""时间"；"全部"复选框；底部统计；底部按钮：更多、创建、隐藏、清除、返回。下拉刷新加载较新的，底部"更多"加载较早的（从服务器）
- 应用卡片（`item_app_card.xml`，`AppCardContainer.setupCardData`）：所有者头像、标准名称、所有者（有 CID 显示 CID，否则 FID）、类型（逗号分隔）、总币天销毁（`tCdd`，K/M/B 缩写）、总评分（`tRate`，一位小数）；右侧评分图标（所有者是自己时不显示）、编辑图标和上链状态图标（只对自己的条目显示）
- 服务卡片（`ServiceCardContainer`）：同上，类型是单个字段（`type`）
- 点卡片 → 详情（`DetailActivity`/`DetailFragment`）：列出登记的全部字段；有评分按钮、"生成二维码"、"复制 JSON"。网址不能直接点开
- "更多"菜单（`popup_menu_app_more.xml`/`popup_menu_service_more.xml`）："关于应用"/"关于服务"、"我的应用"/"我的服务"、"刷新"、"已停止"、"关闭"、"停止"、"隐藏"（即已隐藏列表）
  - 关于应用（`about_app_message`）："应用是去中心化应用程序的链上登记条目（协议 FEIP-15）……任何人都可以发布。没有应用商店的把关者……记录元数据。名称、类型、主页链接、下载入口，以及它所依赖的协议、服务和代码……它的 ID（aid）就是发布它的那笔交易。"
  - 关于服务（`about_service_message`）："服务是去中心化服务的链上登记条目——API 端点、存储、中继或其他组件（协议 FEIP-5）……记录元数据。端点、可选的定价，以及它所用到的协议和代码的链接……它的 ID（sid）就是发布它的那笔交易。服务让应用能够在网络中发现并连接到各个提供者。"
- 隐藏（底部"隐藏"按钮，`handleHideApps`）：勾选的条目加入本地删除名单，从本机列表移除，只影响本机，不上链；"更多"→"隐藏"里可选中再"显示"
- ID：应用的 ID 叫 aid，服务的叫 sid，都是发布它的那笔交易的 txid（FEIP15、FEIP5V3）
- 掌柜与服务员：服务有 `dealer`（掌柜，FID，界面"掌柜"），负责业务收支；应用（FEIP15）没有掌柜字段。应用和服务都有 `waiters`（服务员，"FIDs to notify"，创建页"服务员（逗号分隔）"），接收客户消息
- 协议、代码：主页另有"协议"（`menu_protocol`）、"代码"（`menu_code`），列表、详情、评分、隐藏等操作与应用、服务相同
- 停止、关闭、恢复、编辑：只有所有者能做（FEIP5/FEIP15 的 stop/close/recover/update），本集不讲
- 评分（`RateActivity`，`activity_rate_app.xml`）：标题"评价应用"/"评价服务"；显示"评价此应用"、总币天销毁、总评分；"评分用钞票"，"币天越高 = 权重越大"，选钞票后显示"总币天: N"；"选择评分"0–5（"5 - 优秀"……"0 - 很差"）；"原因"（"评价原因（可选）"）；底部清除、评分、返回。总币天为 0 提示"总币天必须大于0"；成功提示"评分提交成功！交易: …"
- 评分规则（FEIP5V3 / FEIP15 rate）：所有者不能给自己评分；分量是这笔交易的币天销毁；`tRate` 是按币天销毁加权的平均分，`tCdd` 是所有评分的币天销毁之和；`cause` 只记在历史里，不影响分数
- 选择服务（`ServerSetupActivity` → `ServicePickerUtils.pickerIntent` → `SetDiskActivity`，布局 `activity_change_api_service.xml`）：主页"设置"→"设置链上服务器"→"高级设置…"→ DOCK、DISK、BASE、CALL、ROAD 各有选择按钮；选择页按类型过滤，排序"时间""评分""币天销毁"；选中后把服务 ID 填进输入框
- 设置链上服务器（录屏所见）：Tom 已登记过服务器，从主页右上角菜单"设置链上服务器"直接进入完整表单（BASE、DOCK、DISK 各有输入框和搜索按钮），没有"高级设置"一步；DISK 的搜索按钮打开"文件服务器（DISK）"选择页，顶部是当前 DISK，每张卡片有 ID、所有者、掌柜、API 地址、评分和币天销毁
- 应用详情（录屏所见，MyCoins）：标准名称、本地名称、类型、描述、版本、主页、下载、协议、代码、所有者；没有服务字段
- 服务详情（录屏所见，Fast FAPI）：类型 FAPI@No1_NrC7、描述、组件（BASE、DISK、MAP、ROAD、DOCK）、主页（api: fudp://fapi.cid.cash:8500）、所有者、总 CDD、总评分；没有价格字段
- 评分提交后进入"发送交易"页：付给 Tom 自己，显示总值、交易费、币天销毁和上链内容（FEIP15 rate），点发送后回到列表，提示"交易已发送，需1-5分钟确认"
- 已知问题（不影响录制，供修正）：`ServiceActivity` 搜索成功的提示用了 `found_apps_count`，显示"找到 N 个应用"；隐藏后的提示是英文"Hidden 2 service(s)"；DISK 选择页提示"获取到 3 个API服务"
- 读音（`READINGS`）：BASE、DOCK、DISK 按 U1-06 的读法；合成前跑 `readings.py`

## 场景

### S1 [讲师] 开场

> 手机上装什么应用，常常要看应用商店让不让上架。
> 应用中的数据来源，也大多是应用开发商替你定好的。
> 在自由宇宙里，应用和服务都登记在链上，谁都能发布，你可以自己挑选替换。

### S2 [动画] 链上的应用与服务目录

标注：动画（新）。每句一步——
①左边一座带门卫的"应用商店"，几个应用被挡在门外；右边一条链，几张登记卡片直接刻上去，没有门卫；
②一张"服务"卡片：一台服务器图标，标签 BASE、DOCK、DISK，旁边一个计费器；
③一张"应用"卡片：一部手机图标，连线指向两三张服务卡片；
④卡片放大：所有者头像和 CID、名称、类型；ID 一栏从一笔交易引出，应用标"AID"，服务标"SID"；
⑤服务卡片下挂出两个小头像："掌柜"旁一个钱袋，"服务员"旁一个消息气泡；虚线连到所有者；
⑥几个人各烧一点币天给它打分，灰烬汇成"总币天销毁"，分数汇成"总评分"；一个 100 cd 的 5 分压过几个 1 cd 的 0 分；
⑦所有者头像旁亮起它的重量和声誉

> 主页的应用和服务，是两份登记在链上的目录。任何人都能发布，没有谁审批上架。
> 服务，是别人运行着的服务器，比如提供链上数据的 BASE、保存消息的 DOCK、保存文件的 DISK，按用量收费。
> 应用，是你装在设备上使用的软件，它要连接各种服务才能工作。
> 每条登记都记着应用或服务的所有者、名称和类型，有它自己的 ID，应用的 ID 叫 AID，服务的 ID 叫 SID，都来自链上发布时的交易 ID。
> 服务除了所有者，常常还有一个掌柜，处理业务收支；应用和服务还会有一两个服务员，处理客户消息。如果都没有，有问题你可以直接联系所有者。
> 用过的人可以打分，按照评分交易的币天销毁加权记分。
> 所有者也是一个飞人，它的链上信用公开可查，不放心应用或服务，可以看看所有者是否可信。

### S7 [讲师] 结尾

> 应用和服务，谁都可以发布，谁也不能替你决定用哪个。
> 判断的依据都在链上：谁发布的、多少人用币天投过票、分数多少。
> 你的每一次评分，也会成为别人挑选时的参考。
> 协议和代码的基本操作跟应用和服务一样，只是普通用户一般不关心，成为开发者时才会用到。

### S8 [卡片] 要点

- 应用和服务登记在链上，谁都能发布
- 服务是收费的服务器，应用连接服务后才能工作
- 评分用评价的币天销毁加权
- DOCK、DISK 等服务可以自己挑选设置

> 记住这四点。
