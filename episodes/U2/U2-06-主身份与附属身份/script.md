## 目标

看完这一集，观众能够：
- 知道主身份和附属身份的区别：登录的、在本机保存私钥、购买服务的是主身份；没有私钥、借用主身份的服务查看的是附属身份；
- 知道附属身份都是观察身份：主人、仆人、多签是和主身份有特殊关系的观察身份，"观察名单"里的是没有关系的观察身份；
- 认识身份菜单：当前是主身份时，可以从"我的主人""观察名单""我的多签""我的仆人"切换到附属身份；在附属身份里点"主身份"回来；
- 用"观察名单"添加任何一个 FID 或 CID，切换过去看它的余额、钞票和记录；
- 知道同一个身份作为主身份登录和作为附属身份查看，主页不同：附属身份的主页多一个"没有私钥"图标，需要私钥的社交和数据功能（数据、广场、团队、房间、对话）都不显示；
- 知道多签身份略有不同：主身份可能持有其中一把成员私钥，能签上自己的一份，但凑不齐签名就完不成交易；多签身份没有自己的密钥对，不能加密解密；
- 知道附属身份只能看，不能签名：要付款，飞人只能做出未签名的交易，交给有私钥的设备去签。

本集独立成篇，不承前启后。

## 核对依据

- 主身份与当前身份：`FidManager` 里分 `mainFid`（登录的身份，持有设置和服务连接 `ApiCenter`）与 `liveFid`（当前操作的身份）。切换 `liveFid` 只重新加载这个身份的钞票、联系人、密信、秘密等数据（`reloadManagers`），服务连接仍是主身份的
- 附属身份都按观察身份处理：本机只有它们的 FID 和公开信息，没有私钥（`prikeyCipher` 为空）。观察名单加入的身份 `setWatchOnly(true)`；主人、仆人、多签只是来源不同（分别从"我的主人""我的仆人""我的多签"从链上查出），切换过去同样只能看
- 身份菜单（`popup_menu_person.xml`）：顶部"当前活跃身份"一栏实际显示英文"Living: Main FID / Master / Watched / Multisig / Servant"（`PersonPopupMenuHelper.setupPopupContent`）；下面"主身份""我的主人""观察名单""我的多签""我的仆人""退出主身份"。当前是主身份时"主身份"变灰；当前不是主身份时"我的主人""观察名单""我的多签""我的仆人"变灰，只能点"主身份"切回（不弹确认，直接切换，提示"切换身份成功"）
- 主身份必须能签名：导入只有公钥或 FID 的密钥时提示"主FID必须能签名，而这里没有私钥。请登录后在"观察的FID"中添加。"（`key_watch_only_not_main`）
- 观察名单：身份菜单 →"观察名单"→"选择观察FID"页（空时"没有可用的观察FID"），底部图标：添加（加号）、返回 → 点添加 →"添加观察FID"页，输入框提示"输入要观察的FID或CID"，右侧放大镜搜索 → 点结果卡片选中 → 点对勾添加，提示"观察FID添加成功"（已在名单里提示"该FID已在观察列表中"）；加入的身份标记为仅观察（`AddWatchedFidActivity.confirmAddWatchedFid`，`setWatchOnly(true)`）→ 回到列表，点卡片即切换过去（"切换FID中"）
- 附属身份的主页（`HomeActivity`）：
  - 身份卡片：当前身份没有私钥时，名字旁显示"没有私钥"图标 `ic_no_prikey`；多签身份（FID 以 3 开头）显示"多人"图标 `ic_people`，点它打开"多签详情"（`setupLiveFidCard`、`setMultisignIconListener`）
  - 功能菜单：当前身份不是主身份时，隐藏"数据""房间""团队""对话""广场"五项（`updateMenuVisibilityForLiveFid`，代码注释："These functions require mainFid's private key and home services."）
- 多签身份：FID 以 3 开头，本身没有密钥对。付款时飞人按多签信息构建交易，进入"签署多签交易"页（`TxSender.getMultisigOfSender`、`SignMultisigTxActivity`），用本机的成员私钥签上自己的一份，选的密钥不是成员时提示"所选密钥不属于此多签交易"；要凑够规定数量的成员签名才能"完成多签交易"。不能加密解密："多签 FID 没有密钥对，无法加密或解密消息，因此无需设置 DOCK/DISK。"（`server_setup_not_for_multisig`）
- 没有私钥时付款：飞人只生成未签名交易（"没有私钥。复制去签名并广播。"，`TxSender` 的 `onUnsignedTx`）
- 我的仆人：以当前身份为主人的 FID，从链上查出（`fapiClient.myServants`）；我的主人：没有主人时弹窗问是否设置（英文弹窗），有则切换到主人

## 场景

### S1 [讲师] 开场

> 在飞人里，你登录的那个身份叫主身份。
> 它的私钥保存在这部手机上，服务也是它买的。
> 除了主身份，你还可以查看别的身份。它们没有私钥，借用主身份的服务，叫附属身份。

### S2 [动画] 附属身份都是观察身份

标注：每句一步——①中间一张主身份卡片，带钥匙图标，连着几台服务器（服务）；②四周出现四张附属身份卡片，都带"眼睛"图标、没有钥匙，统一标"观察"；③其中三张分别加上小标签"主人""仆人""多签"，与主身份之间连上关系线，第四张没有连线，标"观察名单"；④附属身份通过主身份的连线接到服务器上；⑤附属身份卡片上的签名笔被划掉

> 主身份能签名，能付款，能收发消息，连接着它购买的各种服务。
> 附属身份，其实都是观察身份。
> 主人、仆人、多签，是和主身份有特殊关系的观察身份；没有关系的，就放在观察名单里。
> 它们借用主身份的服务，查看自己的余额、钞票和记录。
> 但手机里没有它们的私钥，所以只能看，不能签名。

### S3 [录屏] 观察名单

操作：Tom_9yw4 的主页 → 点顶部"身份菜单"图标 → 菜单弹出，停留，让各项可读 → 点"观察名单" →"选择观察FID"页，显示"没有可用的观察FID" → 点加号 →"添加观察FID"页 → 输入"cy_qqN8" → 点放大镜 → 出现领航员的卡片 → 点选 → 点对勾，提示"观察FID添加成功" → 回到列表 → 点领航员 → 主页变成领航员的头像、FID 和余额，停留两秒
注意：输入时键盘若变黑，剪掉打字过程

> 点"身份菜单"，下面这几项就是附属身份。
> 点"观察名单"，点加号。
> 输入 FID 或 CID，点搜索。
> 选中它，点对勾，加进名单。
> 观察不需要任何关系，任何一个身份都能加。
> 点一下，就切换到这个身份，看它的余额、钞票和记录。

### S4 [录屏] 回到主身份

操作：（接 S3，当前在领航员）点"身份菜单" → 菜单弹出，停留，"观察名单""我的仆人"等几项是灰的 → 点"主身份"，提示"切换身份成功" → 回到 Tom_9yw4 的主页，停留两秒

> 在附属身份里，身份菜单的这几项是灰的。
> 点"主身份"，就回到自己。

### S5 [录屏] 同一个身份，两种主页

操作：（接 S4，Tom_9yw4 是主身份）主页停留，慢慢上下滑动，让功能菜单各项可读，"数据""广场""团队""房间""对话"都在 → 点"身份菜单" →"退出主身份" →"选择身份"里点 cy_qqN8 → 领航员的主页 → 点"身份菜单" → 点"我的仆人" →"选择仆人FID"页 → 点 Tom_9yw4 →"切换FID中" → Tom_9yw4 的主页：名字旁出现"没有私钥"图标，停留 → 慢慢上下滑动，"数据""广场""团队""房间""对话"都不见了，停留两秒
注意：两段主页滑动的速度、位置尽量一致，方便对比；剪辑时可去掉切换身份中间的等待

> 同一个身份，作为主身份登录，和作为附属身份查看，主页并不一样。
> 这是 Tom 作为主身份登录时的主页，功能都在。
> 现在换领航员登录，再从"我的仆人"切换到 Tom。
> 名字旁边多了一个图标，表示这部手机上没有它的私钥。
> 数据、广场、团队、房间、对话，这些社交和数据功能要用私钥，都不见了。

### S6 [动画] 多签身份

标注：每句一步——①一张多签身份卡片（"多人"图标），下面挂着三把成员钥匙的位置，标"三把里要两把"；②其中一把钥匙亮起，属于主身份，签上一个对勾，标"已签 1/2"；③另外两把是灰的，交易卡在"待签"；④多签卡片旁的锁和信封被划掉，标"没有自己的密钥对"

> 多签身份和其他附属身份略有不同。
> 它由几把成员私钥共同控制，比如三把里要两把签名才算数。
> 你的主身份可能就是其中一员，能签上自己的一份。
> 但只有这一份，凑不齐签名，交易就完不成。
> 多签身份也没有自己的密钥对，不能加密，也不能解密。

### S7 [讲师] 附属身份只能看

> 附属身份在这部手机上没有私钥，要用它付款，飞人只能做出一笔未签名的交易，交给有私钥的设备去签。
> 一个常见的用法：私钥放在离线的密库里，联网的手机只观察它，随时看余额，却碰不到私钥。

### S8 [卡片] 要点

- 主身份：私钥在本机，能签名，服务由它购买
- 附属身份都是观察身份：主人、仆人、多签是有特殊关系的观察身份
- 附属身份没有私钥，主页上需要私钥的功能不显示
- 多签只有部分私钥，凑不齐签名
- 在身份菜单里切换，点"主身份"回来

> 记住这五点。
