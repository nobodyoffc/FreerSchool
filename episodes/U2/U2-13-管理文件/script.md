## 目标

看完这一集，观众能够：
- 知道 DID 是由文件内容算出的文件身份，DISK 只按 DID 存取、不管内容，HAT 在本地记着文件的各种属性；飞人上传前先把文件加密成密文文件，原文件的 HAT 记下密文文件的 DID；
- 会在"文件"里添加文件、上传到 DISK；
- 会移除本地文件腾出手机空间，需要时再从 DISK 下载、打开；
- 知道 HAT 只在这部手机上，要用"导出HAT"备份，换手机时导入 HAT，再从 DISK 下载文件。

本集独立成篇，不承前启后。

## 核对依据

- 改名：应用里原来的"数据"（主页入口、页面标题）改为"文件"，英文 Files；相关按钮和提示同步改为"上传文件""下载文件""删除文件""移除本地文件"等。排序和 HAT 详情里的"姓名"改为"名称"（联系人页仍是"姓名"，另设 `person_name`）。已录各集不随之修改
- 入口：主页"文件"（`menu_data` → `DataActivity`，标题"文件"）。只对主身份开放（附属身份提示"文件仅对主 FID 可用，主 FID 持有用于加密的私钥。"）；没有 DISK 时提示先设置
- "文件"页（`DataActivity`）：顶部搜索框，排序"时间""名称""大小"；每张卡片（`HatCardContainer`）显示类型图标、名称、ID（前后各 8 位）、大小、时间，右侧存储位置图标和播放图标（"打开"），复选框常显示；底部统计"显示 N / 共 M"；底部按钮：更多、上传、下载、添加、返回；"全部"复选框
  - 存储位置图标：只在本机 `ic_local`（"本地存储"）、只在 DISK `ic_disk`（"存储在 DISK"）、两处都有 `ic_disk_local`（"存储在 DISK 与本地"）
  - 点卡片打开 HAT 详情；点播放图标打开文件：本机没有就先从 DISK 下载（要私钥解密），再用手机上的应用打开（`HatFileOpener`）
- DID：文件内容的双重 SHA256。同样的内容得到同样的 DID，改动一个字节 DID 就完全不同；DID 只由内容决定，和文件名、存放位置无关
- 添加（`addNewFile`）：系统文件选择器，可多选；文件复制进飞人自己的目录，算出 DID，生成一条 HAT（名称、大小、类型、时间、位置 `local://`）；提示"文件添加成功"。只在本机，没有上传
- 上传（`launchUploadDataActivity` → "上传文件"页 → `UploadService`）：只对勾选的、只在本机的文件；上传页列出这些文件，点"上传"图标开始，回到"文件"页显示进度条，完成提示"上传完成：已上传 N，已跳过 N，失败 N"；DISK 上已有的跳过
  - 加密（`DataSyncManager.uploadData`）：随机生成对称密钥，把文件加密成密文文件，密文文件有自己的 DID（cipherDID）；密钥用当前身份的公钥加密（`kCipher`）；只把密文文件传到 DISK，DISK 按 cipherDID 保存。DISK 拿不到原文，也拿不到密钥
  - 两条 HAT：文件的 HAT（id = 文件 DID，名称、大小、类型，`cipherIds` 指向密文文件的 DID）；密文文件的 HAT（id = cipherDID，`rawDid` 指回文件 DID，`kCipher` 加密后的密钥，`locas` DISK 位置 `fudp://…`）
  - 上传是长期保存（`permanent = true`）；DISK 收费（通知里显示"费用：N sats"）
- "更多"菜单（`popup_data_menu`）："导入HAT""导出HAT""移除本地文件""删除文件"
  - 移除本地文件：对勾选的、本机有文件的；确认框"移除 N 个已选HAT的本地文件？本地文件将被永久删除。HAT记录将保留并更新其位置信息。"；之后卡片变成只在 DISK
  - 删除文件：删除本地文件和 HAT 记录，"此操作无法撤消"（本集不演示）
- 下载（`launchDownloadDataActivity` → "下载文件"页 → `DownloadService`）：只对勾选的、本机没有文件但 DISK 上有的；顺着 `cipherIds` 找到密文文件的 HAT，按 `locas` 从 DISK 下载密文文件，核对 `rawDid`，用私钥解开 `kCipher` 得到密钥，再解密成原文件，存回飞人目录；完成提示"下载完成：已下载 N，失败 N"。中途取消提示"已接收的数据将被丢弃，重新下载将再次计费"
- 导出HAT（`ExportHatActivity`，"导出HAT"）：把 HAT 列表导出为 JSON，**不加密**，存到手机下载目录（`hats_<FID>_<时间>.json`），也可转二维码、复制。里面有文件名、大小、DISK 位置和用公钥加密过的密钥——没有私钥打不开文件，但文件名等信息是明文
- 导出HAT 原来只导出列表里的原文件 HAT（`DataActivity.exportHats` 用的是显示列表，`getHatsSortedByLastDesc` 滤掉了密文文件的 HAT），带着加密密钥和 DISK 位置的密文文件 HAT 没有导出，换手机导入后下载不了。已在应用里修正：导出时把每个 HAT 的 `cipherIds` 对应的密文文件 HAT 一起导出。录屏用的是修正前的版本，画面里 JSON 显示 `"count": 1`，旁白没有提到条数
- "移除本地文件"确认框的按钮原来用 `confirm`（中文"验证"，是给"检查密码"页用的），已在应用里改用 `ok`（"确定"），S4 已重录
- 导入HAT（`ImportHatActivity`）：粘贴、选文件或扫码，把 HAT 加回列表；之后勾选下载即可
- HAT（FVEP10，Hash Attribute Table）：描述一份数据的记录，DID 是唯一联系；DISK 只管按 DID 存取字节，不懂含义。"HAT 很小，传递的是 HAT，不是数据"
- 换 DISK：下载时按 HAT 里记的位置（`fudp://…` 或 `(sid)…`）连接对应的 DISK，不一定是当前登记的那个（`DataSyncManager.getFapiClientForLoca`）；界面上没有"同一文件存多个 DISK"的操作
- DISK 协议（FAPI12V1）：DID 是 SHA256x2，同样内容同一个 DID，DISK 自然去重；`disk.get` 只要 DID，任何付费的人都能取；存（`disk.put`/`disk.carve`）和取（`disk.get`）都按服务商的价格扣费
- 飞人里所有上传都先加密（`uploadData` 没有不加密的选项）：每次用新的随机密钥，同一个文件两人各自上传，密文不同、DID 不同，不会共享
- 聊天里发文件（`FileShareHelper`）：同样先加密上传到 DISK，消息里只发 HAT 的副本，附上明文密钥和 DISK 位置（聊天消息本身用对方公钥加密）；对方按 HAT 下载、解密
- 更换 DISK：主页"设置"→"设置链上服务器"（`ServerSetupActivity`），"文件服务器（DISK）"，发布上链
- S2 里两处只示意、不演示：①一个文件存多个 DISK——应用里一次只能设一个 DISK，上传只针对只在本机的文件，没有存第二个 DISK 的操作，只在动画中表现；②不加密上传公开作品——飞人现在所有上传都加密，旁白只作提示
- 传统文件管理（S2 对比用）：文件按位置找——哪台设备、哪个文件夹、哪个网盘账号；放在网盘上的是原文件，平台能看、能删、能停用账号
- 同步：应用里没有入口（`SyncResultDialog` 未被调用，`HatBackupWorker` 未启用），本集不讲
- 读音（`READINGS`，字幕保留原文）：DISK 按 U1-06 的读法；HAT 读作单词 hat（写成 Hat）；DID 逐字母读（写成 D I D，连写会念成 DIAD、DIED）；合成前跑 `readings.py`

## 场景

### S1 [讲师] 开场

> 照片、合同、视频，这些文件你存在哪里？
> 只放在手机上，手机丢了就没了；放在网盘上，平台能看，也能关。
> 飞人把文件存在你自己选的 DISK 服务器上。
> 隐私文件自己加密，不需要相信 DISK，想换 DISK 就能换。

### S2 [动画] 文件、DID、HAT 与 DISK

标注：动画 DiskHat。每句一步——
①一个人的身份卡片"FID F…9yw4"旁边，一张图片"壁纸.jpg"也挂上一张编号牌"DID"；
②图片下方吐出一串指纹般的编号"DID 3f9a…c21e"；图片改一个像素，DID 整串跳变；
③右边出现几台 DISK 服务器，各带链上信用的星级，飞人选中一台，文件存上去；
④手机向 DISK 发出"DID 3f9a…"，文件传回来，计费器跳一下"扣费"；
⑤DISK 内部一格格按 DID 编号的格子，旁边一个问号脸"不问是什么、干什么用"；
⑥图片旁出现一顶帽子形状的卡片"HAT 哈希属性表"：名称、类型、说明、大小……，帽子上写着 DID，和图片连线；
⑦HAT 留在手机里；从 DISK 取回一个文件，按 DID 找到对应的 HAT，文件旁亮起它的说明；
⑧手机里的 HAT 复制一份成为"备份"文件；
⑨DISK 格子里的原文件，几个陌生人都举着同一个 DID 来取，都拿到了；
⑩一把随机生成的钥匙在手机里把图片锁成一团乱码"密文文件"，再飞向 DISK；
⑪公开作品"我的诗.txt"不经加密直接飞向 DISK，几个人按同一个 DID 取走；
⑫密文文件吐出自己的 DID "DID 8b07…"；原文件的 HAT 上多出一行"密文 DID 8b07…"，箭头指向它；
⑬下载：手机按 8b07… 从 DISK 取回密文文件，用钥匙解开，图片重现；
⑭密文文件在两台信用星级高的 DISK 上各存一份，HAT 上记着两个位置；
⑮聊天：一顶 HAT 从 Tom 的手机飞到对方手机（不是文件本身），对方按 HAT 上的 DISK 位置和密钥取回密文文件、解开

> 飞人有 FID，任何数据，比如这张图片文件，也有 ID，叫 DID，即数据的身份。
> 每个文件都能算出一个唯一的哈希值，就是 DID，内容的任何改变都会让 DID 改变。
> 飞人可以选择自己信任的 DISK 服务商，把文件存上去。
> 需要这个文件时，只要告诉 DISK 它的 DID，就能下载。存和取，服务商都会扣费。
> DISK 只提供简单的存取服务，不关心文件是什么、干什么用，也不做安全分级。
> 每个 DID，也就是每个文件，都对应一张哈希属性表，叫 HAT，也可以叫它帽子，描述这个文件的各种属性，比如它是什么、干什么用。
> HAT 由飞人保存在本地。从 DISK 取回的文件，按 DID 找到它的 HAT，就能了解这个文件。
> HAT 都在本地，如果担心手机损坏或丢失，可以定期导出 HAT 做备份。
> 要注意，DISK 按上传的样子原样保存文件，而且任何人都能按 DID 下载。
> 所以，飞人默认在上传前，先在本地把文件加密成密文文件，再传到 DISK。
> 如果你发布的是公开作品，就可以不加密上传，让大家按 DID 自由共享。
> 密文文件有自己的 DID，原文件的 HAT 会记下密文文件的 DID。
> 在飞人里从 DISK 下载文件时，会先下载密文文件，再解密出原文件。
> 对于重要的文件，可以选择多个链上信用好的 DISK，多存几份备份。
> 在聊天里分享文件，其实只是把 HAT 发给对方，对方用 HAT 里给出的 DISK 和密钥去取回、解密。

### S6 [讲师] 结尾

> DISK 只替你保管密文，钥匙始终在你手里。
> HAT 记着每个文件的特征，包括存在哪个 DISK 上，以后换了 DISK，以前的文件照样能取回。
> 文件可以存在任何 DISK 上，你用 HAT 和加密保障隐私和安全，不再依赖任何第三方。
> 隐私文件自己加密，可公开的文件按 DID 自动共享，不用每人存一份。
> 如果你是 DISK 服务商，也不用操心怎么管理用户和内容，只需要收款、提供存取、扣费就行了。

### S7 [卡片] 要点

- DID 由文件内容算出，是文件的唯一身份
- HAT 记着文件的各种属性
- 更换设备记得导出备份 HAT
- 隐私文件自己加密，公开文件自动共享

> 记住这四点。
